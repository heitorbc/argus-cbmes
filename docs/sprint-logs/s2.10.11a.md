## Por que mudar

**Diagnose feito antes do refactor:**

1. **Dispensas lenta**: era a **única página de cadastro** que ainda usava
   `useEffect+fetch` (escapou da migração em S2.10.9c). Sem `staleTime`,
   sem cache hidratado do localStorage, refazia fetch a cada mount.
2. **Agenda extremamente lenta + dados incompletos**:
   `AgendaService.coletarDoMapaForca` chamava `MapaForcaService.getMapaForcaDoDia(data)`
   30× em sequência para um range de 30 dias. Cada `getMapaForcaDoDia`
   consolida 10+ fontes (~15-20 queries Prisma cada). Resultado: ~300
   operações por request → timeouts silenciosos derrubando dias inteiros
   da resposta. Por isso o Tech Lead via apenas 1 entrada ISEO de junho,
   mas faltavam escalas mensais de maio/julho que existem em Postgres.
3. **AgendaCard**: usava `useEffect+fetch` direto, perdendo o cache do
   `PersistQueryClient` introduzido em S2.10.9c. Cada visita à home era
   nova request.
4. **Link Agenda**: usuário só conseguia chegar à página `/agenda` clicando
   "Ver toda agenda →" do box. Faltava entrada direta no menu Prontidão.

## Entregas

### Backend — fix raiz da Agenda

**[apps/api/src/modules/escalas/escalas.service.ts](apps/api/src/modules/escalas/escalas.service.ts)**

Novo helper público `listEscaladosDoMilitarNoRange(nf, inicioIso, fimIso)`:

- Identifica meses no range via `mesesNoRange()` (tipicamente 1-4 meses)
- 1 `findMany` cobrindo todos os meses com `composicaoEntries` incluídos
- Para cada mês carregado, percorre `diaEquipe` filtrando dias no range
- Para cada dia com equipe atribuída, filtra `composicaoEntries` onde `militar.nf === nf`
- Retorna `Array<{ data, equipe, viatura, funcao }>` ordenado por data

Custo: **1-2 queries Prisma totais** vs **~300 operações antes**.

## Achados

- **Helper novo, não substitui métodos existentes**: `getMapaForcaDoDia`
  segue inalterado e continua sendo usado pelo `/mapa-forca/:data`. Só
  o caminho da Agenda foi otimizado.
- **`mesesNoRange` é puro/testável**: dado range `2026-05-15..2026-08-15`
  retorna `[{2026,5},{2026,6},{2026,7},{2026,8}]`. Cobre transição de ano.
- **Cache invalidation em Dispensas**: usar `queryClient.invalidateQueries`
  em vez de `refreshSeed` é mais limpo e funciona em paralelo (após
  create + edit + remove).
- **Sem regressão de dados em outros consumers de `getMapaForcaDoDia`**:
  o método em si não mudou; apenas a Agenda parou de chamar 30×.
