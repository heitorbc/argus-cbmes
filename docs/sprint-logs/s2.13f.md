## Por que mudar

A entrevista com o Tech Lead estabeleceu como entrega final da série S2.13 que o sistema deve estar **multi-unidade operacional** — isto é, capaz de armazenar escalas, recursos e efetivo de mais de uma unidade simultaneamente, com filtragem pelo escopo de visibilidade do usuário.

Esta sprint:

1. **Habilita escalas multi-unidade** no Postgres (chave `(ano, mes, unidadeId)`)
2. **Semeia dados da 3ª CIA IND COLATINA + PAB Baixo Guandu** para que o Tech Lead valide o fluxo end-to-end como persona admin sem precisar onboarding externo
3. **Fecha o ciclo** S2.13 — após esta sprint, todas as 6 sub-sprints estão entregues; sistema está pronto para piloto multi-unidade

  1. ADD COLUMN `unidadeId TEXT`
  2. ADD FK com ON DELETE SET NULL (escalas órfãs em vez de cascata destrutiva)

## Achados

- **Tests precisaram de atualização significativa**: 4 testes em `unidades.service.test.ts` falhavam pelas contagens de 2 → 4 unidades. Atualizar foi mecânico; reforça que **seed compartilhado é poderoso mas frágil**: cada novo seed obriga atualização nos testes que verificam contagens absolutas.
- **Bootstrap dev (`bootstrapFromFilesystem`) usa 1ª Cia explicitamente**: o `parseEscalaXlsx` lê o nome do arquivo `04 ABRIL DE 2026.xlsx` e popula como 1ª Cia. Para importar escala de outra unidade, prefixo seria necessário no filename (ex.: `3CIA-IND-04 ABRIL DE 2026.xlsx`) — fica como tech debt para S2.14.
- **`MilitarConsolidator` ainda não auto-cria unidades**: o plano original previa isso para LOCALs desconhecidos. Como exigiria refactor da injeção do `UnidadesService` no consolidator + tratamento de race conditions, deixei como S2.14. Hoje LOCALs novos do QDI ficam no `Militar.unidade` como texto mas sem `Unidade` correspondente — admin pode criar manualmente em `/configuracoes/unidades`.
- **`prisma-test-mock` compartilhado**: aceitar tanto `ano_mes` quanto `ano_mes_unidadeId` foi necessário porque outros testes (não-escalas) chegam via mock compartilhado. Discriminar union types com `'X' in obj` é o padrão TS para isso.
- **`composicaoEntry` ainda não tem `unidadeId`**: o relacionamento via `escalaMensalId` já é suficiente para filtragem indireta (escala da 3ª CIA → composições da 3ª CIA). Sem precisar de coluna duplicada.
