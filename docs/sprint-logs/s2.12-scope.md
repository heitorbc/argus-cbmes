## Itens novos identificados durante S2.10.14

### 1. Cleanup de dependência `googleapis`

`apps/api/package.json` ainda inclui `googleapis` (~3MB). Após S2.10.14c, o único caller seria `MapaForcaCiodesService` — que **não usa** googleapis (lê CSV via `fetch`). Avaliar se a dep pode sair:

```bash
rg "from 'googleapis'" apps/api/src
# Esperado: 0 matches → seguro remover do package.json
```

**Esforço:** 15 min (1 grep + `pnpm remove googleapis` + retest).

### 2. PRD v2.3 — consolidação documental

O PRD v2.1 tem várias linhas em §2 e §3 que descrevem o estado antes das S2.10.x:

- "Service Account rejeitada" → na prática, foi usada (Sheets-DB) e removida em S2.10.14
- Tabela de integrações não menciona MapaForcaCiodes como CSV real-time
- Sprints S2.10.5 → S2.10.14 não estão refletidos
- Status "Sprint S5b adiado" → desatualizado (Supabase em prod)

**Esforço:** 1-2h (revisão + nova tabela §2 + cross-link com sprint logs S2.10.5/9d/14a-c).

### 3. Manual: remover env vars órfãs no Render

Pós-deploy de S2.10.14c, as env vars `GOOGLE_SHEETS_SA_KEY_BASE64` e `SHEETS_DB_ID` ainda estão configuradas no dashboard Render. Não causam erro (nenhum code lê), mas são pegada de credencial órfã.

**Esforço:** 5 min (manual no painel Render).

### 4. Postgres como fonte para `mergulho` e `salvamar`

Em S2.10.5 a migration criou tabelas para `ComposicaoEntry` + `EscalaMensal`, mas **não para os recursos auxiliares**:

- `escala.mergulho.porDia` — chefe/motorista/mergulhadores por dia
- `escala.salvamar.porDia` — supervisores por dia
- `escala.avisos` — avisos do parser

Hoje esses campos vêm do **parser XLSX in-memory** a cada request — após boot, ficam só no objeto `EscalaMensal` rehidratado da composição. Para que a agenda do Tech Lead (S2.10.15) cubra Mergulho/Salvamar, o parser precisa ser persistido.

**Opções:**

- (a) Adicionar tabelas `EscalaMensalMergulho` + `EscalaMensalSalvamar` + `EscalaMensalAviso` no Prisma + popular em `EscalasService.upsertNoPostgres`
- (b) Serializar como JSONB em `EscalaMensal.payloadExtra` (1 coluna, schema flexível)
- (c) Manter como está e ler Mergulho/Salvamar do XLSX in-memory (limita feature a usuários com fixture local)

**Recomendação:** (b) JSONB — encaixe direto, sem mais migrations, e cobre `avisos`/`mergulho`/`salvamar` em 1 coluna. Refactor de `EscalasService` é pequeno (encode/decode no upsert/buscarPorMesAno).

**Esforço:** 0.5-1 dia (migration + upsert + retest).
