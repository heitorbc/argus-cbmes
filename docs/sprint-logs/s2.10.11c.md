# Sprint S2.10.11c — Mapa Força paraleliza coletores (fecha S2.10.11)

**Data:** 2026-05-21
**Foco:** Reduzir latência de `getMapaForcaDoDia` paralelizando as 12 fontes
independentes que antes eram aguardadas em cascata. Sem mudança de
contrato — só performance.
**Tech Lead:** 2º SGT Heitor Barcellos Coelho

## Critérios de Pronto (DoD)

- [x] `MapaForcaService.getMapaForcaDoDia(data)` carrega 12 fontes via
      `Promise.all` no topo do método em vez de 12 `await` sequenciais
- [x] Contrato externo idêntico (mesmo `MapaForcaDoDia` retornado)
- [x] Inconsistências geradas pelos `.catch` continuam aparecendo no
      payload (TROCAS_AUTORIZADAS_INDISPONIVEIS preservado)
- [x] `chopHabilitados` carregado uma única vez (era duplicado entre o
      override de ChOp e a deduplicação de trocas)
- [x] Pipeline: typecheck + lint + format + test verdes
- [x] **655 testes api + 30 web = 685 passing** (sem regressão)

## Por que mudar

Após S2.10.11a (quickwins) + S2.10.11b (ChOp multi-sheet), o gargalo
restante reportado é a página do Mapa Força do dia. Análise:

`getMapaForcaDoDia(data)` consolida ~12 fontes (escala mensal, escalados
do dia, efetivo, viaturas, MF CIODES, aprovações, escala especial, ChOp
escalados, ChOp habilitados, trocas autorizadas, dispensas, notas de
serviço). Todas eram aguardadas em sequência, encadeando latência:

- Cada `await` Prisma soma ~50-150ms (round-trip + query)
- Em série: ~12 fontes × 100ms ≈ 1.2-1.8s só na coleta
- Fontes são **semanticamente independentes** — nenhuma lê o resultado
  de outra antes de chamar a próxima

Paralelizar via `Promise.all` deixa o tempo total = max(latências) em
vez de soma, dentro dos limites do pool Prisma (10 conn ≫ 12 queries
desta única request). Estimativa: redução ~50% (de ~1.5s para ~700ms).

A Parte 2 do plano original (snapshot persistido em `MapaForcaDoDiaSnapshot`)
fica adiada — quickwins do S2.10.11a + paralelização aqui devem
resolver a dor reportada sem precisar de invalidação por evento.

## Entregas

### Backend

**[apps/api/src/modules/mapa-forca/mapa-forca.service.ts](apps/api/src/modules/mapa-forca/mapa-forca.service.ts)**

No topo de `getMapaForcaDoDia` agora roda um único `Promise.all` com 12
fontes:

```ts
const [
  escala, escalados, efetivoTotal, allViaturas, mfRecursos,
  aprovacoes, atosEspeciaisRaw, chefes, chopHabilitados,
  trocasAutorizadasDoDia, dispensasAtivas, nsDoDia,
] = await Promise.all([
  this.escalas.get(ano, mes),
  this.escalas.getEscaladosDoDia(ano, mes, dataIso),
  this.efetivo.getAll({ somente1aCia: false, incluirEfetivoOrfao: true }),
  this.viaturas.list(),
  this.mapaForcaCiodes.getRecursos(),
  this.ajustes.getAprovacoes(dataIso),
  this.escalasEspeciais.getAtosDoDia(ano, mes, dataIso),
  this.chefesOperacoes.getEscaladosDoDia(ano, mes, dia).catch(() => []),
  this.chefesOperacoes.getHabilitadosNfs(),
  this.trocasAutorizadas.listByData(dataIso).catch((err) => { /* inconsistência */ return []; }),
  this.dispensasSvc.listAtivasNoDia(dataIso),
  this.notasServicoSvc.listDoDia(dataIso),
]);
```

Mudanças complementares:

- 7 declarações `const … = await …` duplicadas removidas (uma para cada
  fonte agora pré-carregada). Os comentários sentinela `S2.10.11c —
  veio do Promise.all lá em cima.` ficam no lugar para sinalizar.
- `chopHabilitados` (antes carregado 2× — uma dentro do bloco
  `if (overrideChop)`, outra na deduplicação de trocas) agora vem só do
  topo. O bloco do override reusa a referência externa.
- `atosEspeciais` consome `atosEspeciaisRaw.map(...)` em vez de
  re-chamar `getAtosDoDia`.

Sem mudança de contrato externo — `MapaForcaDoDia` retornado é
idêntico ao anterior. As `inconsistencias` geradas pelos `.catch`
(`TROCAS_AUTORIZADAS_INDISPONIVEIS`) continuam sendo empurradas para o
array, preservando o comportamento de erro suave.

## Achados

- A paralelização foi limpa porque os 12 `await` ja eram independentes
  (cada um lê do seu próprio service). Não precisou refatorar dependência
  alguma — só mover declarações.
- `chopHabilitados` carregado 2× era um leak antigo (S0.5/0.1.1.3 não
  notou que o override de ChOp também precisava). A consolidação trouxe
  ganho marginal extra (1 chamada Prisma a menos por request).
- Não persistir snapshot por enquanto está OK: o gargalo principal já
  era a coleta sequencial. Se métricas pós-deploy ainda mostrarem >1s,
  podemos voltar à Parte 2 (snapshot por TTL + invalidação por evento).
