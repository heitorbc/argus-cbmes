## Por que mudar (e por que era menor que parecia)

O escopo S2.12 documentado em [s2.12-scope.md](s2.12-scope.md) §4 dizia:

> Em S2.10.5 a migration criou tabelas para `ComposicaoEntry` + `EscalaMensal`, mas **não para os recursos auxiliares** (`escala.mergulho.porDia`, `escala.salvamar.porDia`, `escala.avisos`).

Auditoria do código mostrou que essa afirmação **estava errada**:

1. **[apps/api/prisma/schema.prisma:204-209](../../apps/api/prisma/schema.prisma)** — `EscalaMensal` tem colunas `avisos Json?`, `mergulho Json?`, `salvamar Json?` desde S2.10.1
2. **[apps/api/src/modules/escalas/escalas.service.ts:416-454](../../apps/api/src/modules/escalas/escalas.service.ts)** — `upsertNoPostgres` serializa os 3 campos com tratamento de `JsonNull` para limpar
3. **[apps/api/src/modules/escalas/escalas.service.ts:505-507](../../apps/api/src/modules/escalas/escalas.service.ts)** — `toEscalaMensal` desserializa com fallback robusto

O **buraco real** era a ausência de **testes de round-trip**: nada garantia que o objeto rehidratado fosse igual ao salvo. S2.12b fecha esse buraco.

## Entregas

**[apps/api/src/modules/escalas/escalas.service.test.ts](../../apps/api/src/modules/escalas/escalas.service.test.ts)** (MODIFIED)

3 testes novos no `describe('EscalasService')`:

1. **`S2.12b round-trip: mergulho.porDia + .equipesPorQuinzena sobrevivem upsert`**
   - Salva escala com `mergulho.equipesPorQuinzena.q1.A = { chefe, motorista, mergulhadores: [...] }` e `mergulho.porDia = { '2026-05-01': { mergulho01: 'A' }, '2026-05-15': { mergulho01: 'A', mergulho02: 'B' } }`
   - Lê de volta via `service.get(2026, 5)`
   - Asserta `mergulho01`, `mergulho02`, `chefe.nomeGuerra`, `mergulhadores.length`

2. **`S2.12b round-trip: salvamar.porDia + .equipesPorQuinzena sobrevivem upsert`**
   - Salva escala com `salvamar.equipesPorQuinzena.q2.F = { supervisores: [militar1, militar2] }` e `salvamar.porDia = { '2026-05-02': 'E', '2026-05-20': 'F' }`
   - Lê de volta
   - Asserta letras E/F e `supervisores.length === 2`

3. **`S2.12b round-trip: avisos[] do parser sobrevivem upsert`**
   - Salva escala com `avisos = ['Aviso 1 …', 'Aviso 2 …']`
   - Lê de volta
   - Asserta array idêntico

## Achados

- **A persistência JSONB de mergulho/salvamar/avisos foi implementada em S2.10.1** (commit do schema inicial), não em S2.10.5 nem deixada para depois. O comentário-cabeçalho do `schema.prisma` linhas 13-15 já dizia:

  > JSONB: usado em campos com estrutura aninhada complexa cujo round-trip 100% é mais barato que normalizar (MapaForcaDiario.payload, **EscalaMensal.avisos, composicaoPorQuinzena.mergulho/salvamar**).

- **O agente que escreveu [s2.12-scope.md](s2.12-scope.md) não auditou o schema atual** antes de listar o débito — leu apenas a história da PR #90 e supôs persistência incompleta. Lição: sempre verificar `git grep` do schema antes de afirmar "X não foi feito".

- **S2.10.15 não precisa de S2.12b como bloqueador**: já pode consumir `mergulho.porDia` + `salvamar.porDia` direto do Postgres. A sub-sprint segue como pré-requisito apenas no sentido de "garantia de cobertura de testes" — não de "viabilidade técnica".
