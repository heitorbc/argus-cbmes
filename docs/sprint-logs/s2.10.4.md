## Mudanças por área

### Backend

- **`schema.prisma`**: User ganha `email String? @unique` e `nomeGuerra String?`. Migration `20260517210000_s2_10_4_user_email_nomeguerra` aplicada via `prisma migrate deploy` no Supabase (após gerar SQL via `prisma migrate diff` + criar arquivo manual, pq `migrate dev --create-only` exige TTY no terminal não-interativo).
- **`auth.service.ts`**: `login()` chama `tryProvisionFromEfetivo` se User não existe (race-safe via try/catch no create + re-fetch). `changePassword()` valida email único e exige no 1º acesso. `toSession()` propaga nomeGuerra + email. Novo método `resetPasswordByEmail()` sem senha atual.
- **`auth-supabase.service.ts`** (novo): wrapper sobre `@supabase/supabase-js` com `requestPasswordReset` (busca email do User → chama Supabase) e `validateResetToken` (Supabase valida o token e retorna email). Tolerante a env vars ausentes (warn + 503).
- **`auth.controller.ts`**: 2 endpoints novos públicos — `POST /auth/forgot-password` (body `{nf}`) e `POST /auth/reset-password` (body `{accessToken, novaSenha}`).
- **`auth.module.ts`**: importa `EfetivoModule` para injetar `EfetivoService`; registra `AuthSupabaseService`.
- **Env vars novas** (Render): `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_RESET_REDIRECT_URL` (opcional — default deriva de `WEB_ORIGIN`).

### Frontend

- **`PasswordInput.tsx`** (novo, `apps/web/src/components/`): forwardRef + toggle olho aberto/fechado (SVGs inline) + lista 4 critérios marcados em tempo real (✓ verde / ○ cinza) usando `senhaCriteriosAtendidos`.
- **`trocar-senha.tsx`**: substitui `<input type=password>` por `PasswordInput` via `Controller`. Campo email aparece sempre, obrigatório só no 1º acesso (refinement Zod dinâmico baseado em `user.primeiroAcesso`).
- **`login.tsx`**: import `StatusBar` e renderiza no rodapé. Link "Esqueci a senha" preserva NF via query param.
- **`esqueci-a-senha.tsx`** (novo): form NF → POST `/auth/forgot-password`. Sucesso → tela "Email enviado". Erro 400 (sem email cadastrado) → mensagem explícita "Contate o administrador".
- **`reset-password.tsx`** (novo): captura `access_token` do `window.location.hash` (Supabase manda no fragment), limpa o hash, pede nova senha + confirmação via `PasswordInput`. Submit → POST `/auth/reset-password` → atualiza sessão e redireciona pra `/`.
- **`home.tsx`**: usa `formatDisplayName(user)` (já existia em `shared-types`) em vez de `{user.posto} {user.nome}`.
- **`router.tsx`**: 2 rotas novas em `PublicOnlyRoute`: `/esqueci-a-senha` e `/reset-password`.
- **`lib/api.ts`**: métodos novos `forgotPassword(nf)` e `resetPassword(accessToken, novaSenha)`.

### Shared types

  - `senhaForteSchema`: 8 chars + regex 3 critérios

## Pré-requisito (Tech Lead — configurar antes de deploy ir live)

No painel Supabase do projeto:

1. **Authentication → Providers → Email**: habilitar
2. **Authentication → Email Templates**: editar template "Reset Password" em PT-BR (referenciar `{{ .ConfirmationURL }}`)
3. **Authentication → URL Configuration**: adicionar `https://<frontend>/reset-password` em "Redirect URLs"
4. **Project Settings → Auth → SMTP Settings**: opcional configurar SMTP próprio; default Supabase já funciona para testes

No Render (env vars):

| Key                           | Value                                          |
| ----------------------------- | ---------------------------------------------- |
| `SUPABASE_URL`                | `https://<ref>.supabase.co`                    |
| `SUPABASE_SERVICE_ROLE_KEY`   | service_role key do Supabase (Settings → API)  |
| `SUPABASE_RESET_REDIRECT_URL` | `https://<frontend>/reset-password` (opcional) |

Sem essas envs, `forgot-password` responde 400 "Recuperação por email ainda não foi configurada".

## Riscos identificados

| Risco                                                            | Mitigação                                                                                     |
| ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Supabase Auth Email pede config de SMTP em prod                  | Default funciona pra testes; Tech Lead configura quando quiser maior controle                 |
| Auto-provision pode criar User pra NF errada (typo)              | Validação Zod no NF + check existência no EFETIVO; militar precisa estar no QDI/EFETIVO sheet |
| Email único pode colidir com email pré-cadastrado por outro user | Backend valida + retorna 409 explícito                                                        |
| Token Supabase expira (default 1h)                               | Frontend exibe "Link inválido" + redireciona pra `/esqueci-a-senha`                           |
