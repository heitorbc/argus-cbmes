## Estratégia "checklist hardcoded por tipo"

MVP usa um `Record<TipoViatura, readonly string[]>` em shared-types.
Vantagens:

1. **Zero infra adicional** — sem CRUD de checklist, sem tabela, sem
   página `/cadastros/materiais`.
2. **Tipável e centralizado** — uma alteração no JSON é uma alteração
   de schema (Zod garante).
3. **Migração futura para tabela em S5b** — mantemos o helper público
   `checklistPadraoPorTipo(tipo)` como ponto de extensão.

Quando o Tech Lead quiser editar a lista, basta abrir o arquivo
`packages/shared-types/src/conferencia-materiais.ts`. Não há fricção
de RBAC ou deploy nessa fase.

## Mapeamento Pendências → Parte Diária

Em `ParteDiariaService.gerarRascunho`:

```ts
textoAlteracaoAlmoxarifado: gerarTextoAlteracaoAlmoxarifado(
  this.materiais.listarPendenciasDoDia(dataIso),
),
```

Cada pendência vira uma linha numerada no formato:

```
1. ABTS 011: Mangueira de 38mm × 2 (Faltando — Faltou 1 unidade).
2. AR 044: Maca rígida (Danificado).
```

Sem pendências → "Não houve." (mesmo placeholder de antes).
O Fiscal sempre pode sobrescrever via PUT `/parte-diaria/:data`.

**Manual (frontend, http://localhost:5173):**

1. Persona "BRUNO MELO" (chefe_equipe) ou "HEITOR" (admin) → Prévia do
   dia → conferir viatura (ex.: `/servico/2026-05-04/conferencia-viatura/ABTS%20011`).
2. Página mostra seção "Conferência de Materiais" com checklist
   padrão do tipo ABTS.
3. Marcar 1 item como **AUSENTE** + observação → "Salvar materiais"
   → mensagem "✓ Materiais conferidos."
4. Abrir `/parte-diaria?data=2026-05-04` → seção "Alteração de
   Almoxarifado" mostra a pendência formatada (`1. ABTS 011: ...`).
5. Editar o texto da PD → o override sobrescreve o derivado (verifica
   que persiste após reload).

## Achados durante a implementação

- **Sobrescrever em vez de versionar:** a conferência guarda só o
  estado mais recente por data/vtr. Histórico fica no servidor de
  Servico (`AlteracaoDiversa` quando relevante). Decisão alinhada com
  ConferenciaViaturaService (S6b).
- **Reset de `materiaisOk` ao editar item:** depois de salvar, se o
  usuário ajusta qualquer item o checkmark verde some, evitando dar
  ilusão de que está persistido.
- **ParteDiariaService dependência cíclica em potencial:**
  `MateriaisModule` importa `ViaturasModule`; `ParteDiariaModule`
  importa ambos `PreviaModule` (que importa ViaturasModule) +
  `MateriaisModule`. NestJS resolve sem problema porque módulos
  compartilhados são singletons. Sem necessidade de
  `forwardRef`.
