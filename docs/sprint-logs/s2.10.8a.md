## Motivação

Em uso real foram identificados 3 problemas (relatados pelo Tech Lead):

1. **Lentidão** — `GET /mapa-forca?data=...` toca 9-11 planilhas em cascata; sem cache, chega a **45-60s**.
2. **Menu de integrações incompleto** — 5 sources não apareciam em `/configuracoes/integracoes` (ISEO Hospitais, QDI 1ª1º, QDI DADOS, Mapa Força CIODES, Sheets-DB).
3. **Inconsistências silenciosas** — fetch falha → `.catch(() => [])` retorna lista vazia sem avisar Tech Lead na UI.

Esta sprint é a **primeira de 4 sub-sprints** (estratégia incremental do plano S2.10.8) e foca em:

- Infraestrutura: scheduler central + auditoria
- Completar o menu de integrações com TODAS as planilhas
- Integrar Dispensas (única já persistida) no orchestrator

As próximas sprints (S2.10.8b/c/d) migrarão TrocaAutorizada, ISEO Hospitais e Militar (Efetivo+QDI) para Postgres + sync, reduzindo o tempo do GET /mapa-forca para sub-segundo.

**Decisão D2 do plano:** MAPA FORÇA CIODES permanece real-time (alta frequência de atualização direta na planilha pelo Comando). Aparece no menu com badge "⚡ Tempo-real".

### Parte B — Schema SyncLog

[apps/api/prisma/schema.prisma](apps/api/prisma/schema.prisma):

```prisma
model SyncLog {
  id           String   @id @default(cuid())
  fonte        String   // 'dispensas-import', 'trocas-autorizadas', ...
  status       String   // 'success' | 'failed' | 'partial'
  created      Int      @default(0)
  updated      Int      @default(0)
  skipped      Int      @default(0)
  erros        String[] @default([])
  trigger      String   // 'startup' | 'cron' | 'manual'
  duracaoMs    Int      @default(0)
  iniciadoEm   DateTime
  finalizadoEm DateTime @default(now())

  @@index([fonte, finalizadoEm])
  @@map("sync_logs")
}
```

### Parte C — SyncOrchestratorService

[apps/api/src/modules/sync-orchestrator/](apps/api/src/modules/sync-orchestrator/):

- `SyncSource` interface — implementada por services persistíveis (id, nome, forceSync, getSyncStatus)
- `SYNC_SOURCES` token DI — array de sources injetado pelo module
- `onModuleInit` → `void syncAll('startup')` (fire-and-forget, não bloqueia boot)
- `@Cron('0 0 0,6,12,18 * * *')` → `syncCron()` → `syncAll('cron')`
- `syncAll(trigger)` → roda todas em paralelo, grava 1 SyncLog cada
- `syncOne(id, trigger)` → para sync específica (admin)
- `getHistory(fonte?, limit)` → últimos N logs ordenados DESC
- `getAllStatuses()` → snapshot in-memory para dashboard
- Classificação automática de status:
  - `success` — sem inconsistências
  - `partial` — algo criado/atualizado mas com inconsistências
  - `failed` — exceção OU 0 criado/atualizado + inconsistências
