## Verificação end-to-end

```bash
# Login
curl -X POST http://localhost:3000/auth/login -H "Content-Type: application/json" \
  -d '{"nf":"3037509","senha":"<sua-senha>"}' -c /tmp/c.txt

# Antes de gerar a Prévia, importe a escala de abril 2026 em /cadastros/escalas
# (web) ou via curl preview+confirm (api).

# Gera a Prévia do dia 23/04/2026 (CHARLIE)
curl "http://localhost:3000/previa?data=2026-04-23" -b /tmp/c.txt | jq '{
  data, equipe, equipeNome,
  fiscal: .fiscal | {militarNf, nomeGuerra: .militarResolvido.nomeGuerra, origem},
  tripulacao: (.tripulacao | length),
  ideo: (.ideo | length),
  viaturasOperacionais: (.viaturasOperacionais | length),
  inconsistencias: (.inconsistencias | length)
}'
# Esperado: equipe="C", equipeNome="CHARLIE", Fiscal=BARCELLOS (default por menor ANT),
# tripulação ≥ 5, IDEO = 2 (ABTS+RESGATE), inconsistências variáveis conforme estado dos cadastros.
```

Frontend: http://localhost:5173 → home tem novo card vermelho "Prévia do Mapa Força" em
destaque → seleciona data → vê composição completa.

**Cenário institucional canônico (PRD §5 + Plano S4):** ao escolher 23/04/2026,
deve aparecer:

- Equipe CHARLIE (sky-blue background)
- Fiscal: 2ºSGT BARCELLOS (origem = "default" — menor ANT 418)
- Composição: ChAbts BARCELLOS, Mot VICENTE, Op1 MARTINELLI, ChResgate KARINA, Sent. CAUÊ LYRA…
- IDEO: itens cadastrados para dia 23 (ABTS, RESGATE)
- Viaturas operacionais: filtra status `operacional`

## Achados durante a implementação

- **Matching tolera o "D. MATTOS" do XLSX vs "MATTOS" do QDI** via tokenização
  (descarta tokens de 1 char). Coberto em test.
- **Acentos no nome de guerra** (`CAUÊ LYRA`) tratados pela normalização NFD +
  remoção de combining marks. XLSX e QDI podem usar com/sem acento — match OK.
- **Inconsistências separadas em 6 tipos discriminados** (`SEM_ESCALA_NO_MES`,
  `EQUIPE_NAO_ESCALADA_NO_DIA`, `NF_NAO_RESOLVIDO`, `AMBIGUIDADE_NOME`,
  `FISCAL_SEM_NF_RESOLVIDO`, `IDEO_NAO_CADASTRADO`, `VIATURA_DESCONHECIDA`)
  permite que telas futuras (S6, S10) tomem decisões diferentes para cada caso.
- **`isFiscal=true`** é setado em pós-processamento, depois que o Fiscal é
  calculado, varrendo a tripulação resolvida. Evita coupling do cálculo com
  a iteração de composição.
- **Mocks dos services** nos testes usam classes TS simples (não vi.fn) — são
  pequenos e contém só o método consumido. Mais legível que mocks dinâmicos.
