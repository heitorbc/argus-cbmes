# Sprint S2.10.7e — Fix sync de dispensas: auto-upsert Militar + sequenciamento de datas

**Data:** 2026-05-18
**Tech Lead:** 2º SGT Heitor Barcellos Coelho — NF 3037509
**PR:** TBD

## Motivação

A sync do S2.10.7d entrou em produção mas falhou silenciosamente:

```
✓ Sync OK — criadas: 0, atualizadas: 0, puladas: 66 (66 inconsistências)
```

Investigação revelou **2 causas distintas**:

1. **Tabela `Militar` em Postgres estava vazia.** O schema foi criado em S2.10.1 mas nenhum código popula a tabela — `EfetivoService` consolida 3 fontes CSV em memória, sem persistir. O guard `prisma.militar.findUnique` em `dispensas-import.service.ts:142-153` rejeitava 100% das linhas com "Militar NF X não existe no banco".
2. **Sequenciamento de tipos errado.** Linha do JARDEL (NF 2967316) com VI=6 e VII=2 em 04/01/2026 gerava 2 dispensas, ambas com `dataInicio=04/01`. O correto é sequenciar: VI cobre 04-09/01 (6 dias) e VII inicia em **10/01** (= 04/01 + 6 dias).

## DoD (S2.10.7e)

- [x] **Parte A** — Parser sequencia datas dentro de cada linha (`próxima = anterior + dias`). Helper `addDaysIso` (UTC-safe).
- [x] **Parte B** — `DispensasImportService` faz auto-upsert em `prisma.militar` antes de inserir Dispensa quando NF não existe em Postgres MAS existe no `EfetivoService.getAll()`. Helper `militarToPrismaData` mapeia 30 campos do shared-types para o shape Prisma.
- [x] **Parte C** — `makeDispensasPrismaMock()` ganha `militar.upsert` (existia só `findUnique`).
- [x] **Parte D** — Tests do parser ajustados (3 verificam sequenciamento: JARDEL VI/VII, ESMAEL I/V, SCARAMUSSA V/VI/IX). Tests do service: removido pre-seed antecipado, adicionados 2 novos (auto-upsert e sequenciamento), 1 atualizado (semântica "nem Postgres nem efetivo").
- [x] Typecheck + lint + format:check + build + tests verdes (**639 testes**: 609 api + 30 web).

## Mudanças

### Parte A — Sequenciamento

[apps/api/src/modules/dispensas/dispensas-2026-import-csv-parser.ts:103-130](apps/api/src/modules/dispensas/dispensas-2026-import-csv-parser.ts)

```ts
// ANTES — todas as dispensas da linha começavam na MESMA data
out.push({ ..., data: dataIso, tipo: ..., dias });

// DEPOIS — sequencial:
let dataAcumulada = dataIso;
for (...) {
  out.push({ ..., data: dataAcumulada, tipo: ..., dias });
  dataAcumulada = addDaysIso(dataAcumulada, dias); // próxima MESMA linha
}
```

Helper `addDaysIso(iso, n)` usa `Date.UTC` para evitar problemas de fuso.

### Parte B — Auto-upsert Militar

[apps/api/src/modules/dispensas/dispensas-import.service.ts:121-167](apps/api/src/modules/dispensas/dispensas-import.service.ts)

```ts
// efetivoByNf novo: map para auto-upsert
const efetivoByNf = new Map(efetivoTotal.map((m) => [m.nf, m]));

if (!militarExiste) {
  const fromEfetivo = efetivoByNf.get(militarNf);
  if (!fromEfetivo) {
    // D3: militar realmente desconhecido → inconsistência
    skipped++;
    inconsistencias.push(
      `Militar NF ${militarNf} (...) não existe nem em Postgres nem no Efetivo consolidado`,
    );
    continue;
  }
  // D2: militar do efetivo é persistido em Postgres antes da Dispensa
  const data = militarToPrismaData(fromEfetivo);
  await this.prisma.militar.upsert({
    where: { nf: militarNf },
    create: data,
    update: data,
  });
}
```

Helper `militarToPrismaData(m)` no fim do arquivo mapeia 30 campos opcionais (`undefined` → `null` para o Prisma).
