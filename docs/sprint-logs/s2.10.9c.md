## Comportamento esperado

**1ª visita:** skeleton aparece enquanto o fetch acontece (igual antes).

**Navegação subsequente:**

- Volta de `/efetivo` para `/agenda` e volta para `/efetivo`: dados aparecem
  **instantaneamente** do cache (in-memory + localStorage). Refetch acontece
  em background se `staleTime` expirou.
- Refresh hard (Ctrl+Shift+R): cache do localStorage é hidratado durante o
  boot — UI aparece com dados mesmo antes do 1º fetch responder.

**Auto-refresh** (apenas `/integracoes`): `refetchInterval: 30s` mantém a
lista de sources atualizada enquanto o usuário está na página, igual antes.

### Smoke pós-deploy (Render + Vercel)

1. **DevTools → Application → Local Storage**: chave `ARGUS_QUERY_CACHE_v1`
   com snapshot do cache (~10-50KB)
2. **Devtools → Network**: na 2ª visita a páginas como `/efetivo`, **não**
   há request `GET /efetivo` se dentro do staleTime. Há refetch em background
   se expirou (não bloqueia UI).
3. **Refresh hard**: dados aparecem antes do `GET` retornar (vêm do cache local)
4. **`/configuracoes/integracoes`**: refresh a cada 30s continua acontecendo
   (refetchInterval)
5. **Botão "↻ Atualizar CIODES"** em `/mapa-forca`: continua funcionando
   (não toca o cache do React Query — chama `integracoesSync` direto)

## Achados

- **Cache version v1**: a chave `ARGUS_QUERY_CACHE_v1` permite invalidar
  todo o cache do cliente em uma única troca de versão (`_v2`). Útil
  quando algum endpoint muda o shape (ex: `EfetivoListResponse` ganha
  novo campo obrigatório).
- **Query keys com filtros**: o padrão `['efetivo', search, page, somente1aCia]`
  cria cache por combinação. Trade-off: cache fica maior, mas cada filtro
  responde instantâneo após 1ª busca.
- **`refetchOnWindowFocus: false`** evita o "piscar" típico do React Query
  quando o usuário troca de aba. Pode-se ligar individualmente por query
  se houver caso crítico futuro.
