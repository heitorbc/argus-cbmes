## Por que mudar

Mobile (`pages/dispensas.tsx` 506 linhas; `pages/atestados.tsx` 392 linhas)
ambas têm o mesmo problema em desktop:

- Filtros em form vertical empilhado (sargenteante reabre toda vez)
- Cards stackados ou lista densa sem filtros laterais visíveis
- Form em rota separada ou modal central — perde-se o contexto da lista

A versão WEB resolve com **layout 3-zonas** estável:

- Sidebar filtros sempre visível (288px)
- Tabela larga com sort por coluna
- SlideOverPanel para edit inline (mantém tabela visível atrás com backdrop)

Sargenteante consegue: filtrar → ver tabela → clicar uma linha → editar →
fechar (Esc) → continuar na mesma busca, sem perder contexto.

## Achados

- **Pattern é reutilizável** — Dispensas e Atestados compartilham ~70% da estrutura. Trocas/NS em S2.10.12e seguem o mesmo molde.
- **`MilitarSelect` API** usa `onChange(nf, militar)` (não `onSelect`). Type errors do TypeScript pegaram isso na 1ª pass.
- **`militarRaw` não existe em Dispensa/Atestado** — só `militarNf`. O MilitarSelect resolve o nome formatado quando o usuário busca, mas a entidade armazenada é só NF.
- **SlideOverPanel + Esc fecha + body scroll lock** funciona perfeitamente para form-in-context (UX padrão de Gmail/Linear).
