# Sprint S2.10.8c — ISEO Hospitais multi-sheet em Prisma + sync orchestrator

**Data:** 2026-05-19
**Tech Lead:** 2º SGT Heitor Barcellos Coelho — NF 3037509
**PR:** TBD

## Motivação

Terceira das 4 sub-sprints do **S2.10.8**. Migra `IseoHospitalEntry` (multi-sheet HPM + HIMABA × meses) de fetch real-time por aba (cache TTL 5min in-memory) para **Postgres + sync orchestrator**.

Antes (S0.5/S2.8.1): cada `GET /iseo-hospitais` (ou `/dia/:data`, `/militar/:nf`) iterava todas as N abas configuradas, fazendo `Promise.all` de fetches HTTP. Sem cache: N × 15s timeout. Falha em 1 aba era silenciada com warning.

Agora: leitura direta de `prisma.iseoHospitalEntry` em <100ms. Multi-sheet sync (paralelo) acontece em background pelo orchestrator (cron 00/06/12/18h + startup + auto-sync).

## Smoke test pós-deploy

1. **Sync no startup**
   - Log: `[SyncOrchestratorService] Startup sync: 3 source(s) registradas — dispensas-import, trocas-autorizadas-import, iseo-hospitais-import`
   - SyncLog table tem 3 entries com `trigger='startup'`

2. **`SELECT COUNT(*) FROM iseo_hospitais`** → N
   - Antes: 0 (tabela nunca populada)
   - Após sync inicial: ~50-100+ (depende das abas configuradas)

3. **`GET /iseo-hospitais`** muito mais rápido
   - Antes: cascata de fetch HTTP em N abas (até N × 15s)
   - Depois: query Postgres ordenada por dataIso/unidade/turno (<100ms)

4. **`GET /iseo-hospitais/dia/2026-05-29`**
   - Filtro por dataIso direto em SQL
   - Retorna HPM (1º par) + HIMABA (2º par) do mesmo dia

5. **Menu `/configuracoes/integracoes`**
   - "ISEO Hospitais → Postgres (upsert multi-sheet)" agora com badge **💾 Persistido** (era ⚡ Tempo-real)
   - "Sincronizar todas" no topo roda 3 sources (Dispensas + Trocas + ISEO)
   - "Ver histórico" mostra SyncLogs do iseo-hospitais-import

6. **Falha em 1 aba não bloqueia**
   - Se HIMABA JANEIRO falhar (planilha deletada/renomeada), SyncLog mostra:
     - status `partial` + `erros[]` com a mensagem
     - HPM JANEIRO e demais abas continuam OK
