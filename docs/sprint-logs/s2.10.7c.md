## Motivação

Em uso real no dia 17/05/2026, dois problemas no entregue do S2.10.7b ficaram evidentes:

1. **Aprovar uma troca autorizada NÃO aplicava o swap no recurso.** Exemplo: troca SD MARTINELLI (NF 4750241) → CB BERGI (NF 4152409) como OPERADOR/SOCORRISTA do ABTS_01. Após "Aprovar", a badge virava verde mas o card do recurso continuava mostrando MARTINELLI.
2. **UI duplicava viaturas em duas seções e não unificava Recurso+Viatura.** Cards "soltos" apareciam na Tripulação depois de DRO/TELEFONISTA (ABTS_011, AC_001, AM_002, AR_031, ATB_001, AU_154, TE_110) E as mesmas viaturas apareciam no bloco "Viaturas (status do MF)" standalone — com filtro hardcoded `VIATURAS_ORFAS_OCULTAS`.

Adicionalmente, aprovações estavam em `Map` in-memory (S2.10.7b) e perdiam-se em restart do Render. O Tech Lead decidiu **persistir em Prisma agora** (antecipa parte de S2.10.8).

### Parte A — Persistir aprovações em Prisma

**Schema** [apps/api/prisma/schema.prisma](apps/api/prisma/schema.prisma:548-578):

```prisma
model AprovacaoPreviaItem {
  id            String   @id @default(cuid())
  data          String   // YYYY-MM-DD da Prévia
  tipo          String   // 'troca' | 'dispensa' | 'atestado'
  itemId        String   // trocaApprovalId (troca) ou UUID (dispensa/atestado)
  status        String   // 'aprovada' | 'rejeitada'
  decididoPorNf String
  decididoEm    DateTime @default(now())

  @@unique([data, tipo, itemId])
  @@index([data])
  @@map("aprovacoes_previa_itens")
}
```

**Service refactor** [apps/api/src/modules/mapa-forca/ajustes-previa.service.ts](apps/api/src/modules/mapa-forca/ajustes-previa.service.ts):

**Cascata async** [apps/api/src/modules/mapa-forca/mapa-forca.service.ts:195](apps/api/src/modules/mapa-forca/mapa-forca.service.ts) e [mapa-forca.controller.ts:211-238](apps/api/src/modules/mapa-forca/mapa-forca.controller.ts) — adicionado `await` nas chamadas.

### Parte B — Aprovação aplica swap em composicaoMf

**Helper novo** [mapa-forca.service.ts:1112-1153](apps/api/src/modules/mapa-forca/mapa-forca.service.ts):

```ts
function aplicarTrocaAprovadaEmTripulacao(
  tripulacao: TripulacaoEntry[],
  troca: { substituidoNf?; substitutoNf?; substituidoRaw; substitutoRaw },
  efetivoByNf: Map<string, Militar>,
  inconsistencias: MapaForcaInconsistencia[],
): TripulacaoEntry[];
```

- Skip silencioso quando `substituidoNf` ou `substitutoNf` ausentes (troca sem NF não dá pra aplicar com segurança)
- Inconsistência quando substituto não está no efetivo consolidado
- Idempotente: se o militar atual já é o substituto, o `find` por substituidoNf não encontra ninguém e retorna a tripulação inalterada

**Reordenação em `getMapaForcaDoDia`**:

- `efetivoByNf` movido pra logo após `efetivoTotal` (antes ficava na linha 352, agora linha 119)
- Trocas autorizadas + manuais + statusAprovacao computadas **antes** de `buildComposicaoMf`
- Loop aplica trocas aprovadas em tripulação antes do build
- `composicaoMf` resultante reflete o efetivo real

### Parte C — Recurso unificado com Viatura + filtro standalone dinâmico
