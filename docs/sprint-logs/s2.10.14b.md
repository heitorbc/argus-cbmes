# Sprint S2.10.14b — Deleta módulo `sheets-db/` inteiro

**Data:** 2026-05-28
**Foco:** Etapa 2/3 do roadmap [remocao-sheets-db-roadmap.md](../runbooks/remocao-sheets-db-roadmap.md) — apaga o módulo NestJS `sheets-db/` e seu registro em `app.module.ts`. Sequencial direto após S2.10.14a (que removeu todos os consumers em runtime).
**Tech Lead:** 2º SGT Heitor Barcellos Coelho

## Critérios de Pronto (DoD)

- [x] `apps/api/src/modules/sheets-db/` deletado (5 arquivos: service, module, serializers + 2 testes)
- [x] `app.module.ts`: removido import + `SheetsDbModule` da array `imports`
- [x] Comentário sobre `.env.local` no `app.module.ts` atualizado (sem mais menção a credenciais SA Sheets-DB)
- [x] Pipeline verde: typecheck + lint + format + test
- [x] **636 api + 30 web = 666 passing** (-19 vs S2.10.14a: 9 sheets-db.service + 10 sheets-db-serializers)

## Por que mudar

Após S2.10.14a, ninguém em runtime consome `SheetsDbService`. O módulo era ~600 linhas de código (auth Google via Service Account + readers/writers + serializers + 19 testes) cuja única função era servir bootstrap de tabelas Postgres que já estão populadas há 2 semanas em prod. Apagá-lo:

- Elimina dependência cognitiva sobre "qual é a fonte"
- Reduz bundle e tempo de boot do NestJS (1 módulo a menos para resolver)
- Remove vetor de erro silencioso (credencial SA expirada, Google API rate limit, parsing de rows malformados)
