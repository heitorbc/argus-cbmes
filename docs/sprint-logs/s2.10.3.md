**Data:** 2026-05-17

**PR:** TBD

## Motivação

S2.10.2 entregou AuthService em Prisma + seed dos users em produção. Este sub-sprint avança nos cadastros mestre, mantendo o padrão estabelecido.

Decisão de escopo: **Efetivo (Militar) NÃO migra agora** porque:

1. A fonte de verdade é externa (QDI + EFETIVO via CSV público) — não há "create militar" no app
2. O cache 5min do EfetivoService já elimina latência de re-fetch
3. Persistir em Postgres exige sync periódico (cron) — quebra silenciosamente quando drift entre sheet e DB
4. FKs `Dispensa.militarNf → Militar.nf` no schema serão tratadas em S2.10.5 (Dispensas) via seed pontual antes de habilitar FK enforcement

## Mudanças por serviço

### UnidadesService

- Antes: Map in-memory, seed hardcoded em `onModuleInit`
- Depois: `prisma.unidade.*` + `ensure1aCia()` via `upsert(where: {codigo: '1ª1º'}, create: {...}, update: {})`. Tolerante a banco indisponível no boot (warn silencioso, próxima requisição retenta).
- Métodos novos: todos retornam `Promise<>` (antes eram sync).

### LocaisFaxinaService

- Antes: Map + seed dev em RAM (perdia ao restart)
- Depois: `prisma.localFaxina.*`. Bootstrap dev (`NODE_ENV !== production && !== test`) faz `count()` — se 0, popula 9 defaults idempotentemente.
- Método `reset()` (que só servia pra tests) removido — tests usam mock próprio.

### ViaturasService (híbrido — caso especial)

- Antes: `Map<string, Viatura>` de overrides + merge com MF a cada `list()`
- Depois: MF continua sendo a fonte da LISTA (origem `mapa_forca`), mas os overrides do admin + historicoKm + observacoesDataDas vêm de `prisma.viatura.findMany({where: {deletedAt: null}})`. `persistOverride()` faz `upsert` por prefixo.
- **Ganho concreto:** Restart de backend NÃO perde mais o KM inicial editado pelo admin, nem o histórico de KM por viatura, nem observações datadas da Conferência da Viatura (S6b).
- ADR-009 preservado: status de viatura MF continua só mudando via Conferência.

## Riscos identificados

| Risco                                                             | Mitigação                                                                                    |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `unidades.findById` agora async — calls síncronos legados quebram | Typecheck pegou `RecursosService.create` (único caller) → agora async tb                     |
| `locais_faxina` table vazia em prod (sem seed)                    | Admin cria manualmente no UI; seed dev só roda local                                         |
| Migration `anoModelo Int→String` em prod                          | Postgres aceita ALTER COLUMN SET DATA TYPE TEXT em coluna nullable sem dados — applied limpo |
| Viatura prefixo único colide com seed admin antigo                | Re-import idempotente: `persistOverride` faz `upsert(where: {prefixo})`                      |
