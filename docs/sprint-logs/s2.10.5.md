## Motivação

Sub-sprint 5 da migração Supabase. 3 dos services mais centrais do operacional migram de Map in-memory + Sheets-DB primário para Prisma + Sheets-DB espelho:

1. `NotasServicoService` — único item por NS, com soft delete
2. `EscalasEspeciaisService` — atos individuais com horário (1:N)
3. `EscalasService` — composição de equipes por quinzena (1:N com até 100+ entries por mês)

Padrão estabelecido nos sub-sprints anteriores: **Prisma é fonte primária; Sheets-DB recebe dual-write fire-and-forget** (continua sendo o espelho institucional no Drive). XLSX/XLSM fallback dev preservado mas só roda se Postgres E Sheets-DB estiverem vazios.

## Decisões implementadas

| #                               | Decisão                                                                                                                    | Onde                                             |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Bootstrap one-shot              | Postgres está vazio E Sheets-DB tem dados → importa 1x. Idempotente.                                                       | `bootstrapFromSheetsDbIfEmpty()` em cada service |
| Re-import substitui mês inteiro | `$transaction` deleteMany cascata + create dos novos atos/entries. ADR-014 D4.                                             | `upsertNoPostgres()`                             |
| Dual-write fire-and-forget      | `void this.sheetsDb.replace*(...).catch(warn)`. Postgres é fonte.                                                          | `syncToSheetsDb()`                               |
| Mock de Prisma compartilhado    | Único helper que cobre 5 models. Suporte a `$transaction(cb)` passando self como tx. Normaliza `Prisma.JsonNull`/`DbNull`. | `prisma-test-mock.ts`                            |
| Soft delete em NS               | `deletedAt` nullable; queries filtram. Auditoria preservada.                                                               | `notaServico.deletedAt`                          |

## Pós-merge no Render

Quando o backend subir, no primeiro request vai disparar:

1. `EscalasService.onModuleInit` → bootstrap Sheets-DB → Postgres (se vazio)
2. `EscalasEspeciaisService.onModuleInit` → idem
3. `NotasServicoService.onModuleInit` → idem

Logs esperados:

```
Bootstrap escalas: N meses importados do Sheets-DB → Postgres.
Bootstrap escala especial: N meses importados do Sheets-DB → Postgres.
Bootstrap NS: N entradas importadas do Sheets-DB → Postgres.
```

Se sair "0 importados" significa que Sheets-DB também está vazio — caí no fallback XLSX dev (apenas local).

## Limitações conhecidas (carregadas de antes)

- Round-trip não fiel ao Sheets-DB: campos `avisos`, `mergulho`, `salvamar` não são serializados na ida pro Sheets (documentado em `sheets-db-serializers.ts:13-21`). Postgres preserva 100% via JSONB.
- Diff seletivo por ato em Escala Especial — adiado (carrega de S2.8.2 Parte D não-implementada). Re-import ainda substitui o mês inteiro.
