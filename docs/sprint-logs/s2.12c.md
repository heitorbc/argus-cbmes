## Por que mudar

### Diff seletivo Escala Especial

O upsert antigo fazia `deleteMany({ where: { escalaEspecialId: existing.id } }) + create cascade`. Funcionalmente OK (atos não têm relações), mas:

1. **Perde informação**: re-import de mês idêntico fazia N writes (deletar + recriar tudo) em vez de 0
2. **Sem visibilidade**: log "Escala Especial 05/2026 importada" não dizia se algo mudou
3. **Não escalável**: quando atos passarem a ter relações (futuro: anexar audit trail por ato), delete cascade vira problema

### NomeMatcher.divergencia

`NomeMatcher.resolve(ref)` quando `ref.nf` casa no `byNf` retorna o militar **sem checar se posto/nomeGuerra na ref batem com os do efetivo**. Cenários reais:

- XLSM grava `'CB BM FABRE'` mas QDI tem `'CB FABRE'` (BM extra) → match OK, mas grafia denuncia desatualização da fonte
- XLSM grava `'3º SGT BARCELLOS NF 3037509'` mas Heitor já promoveu para `'2ºSGT'` → match OK por NF, mas posto na fonte está vencido

Antes, essa divergência ficava silenciosa. Agora o caller (e.g. parser de import, agenda coletor) pode logar para o Tech Lead corrigir a fonte upstream.

## Entregas

### Backend

**[apps/api/src/modules/mapa-forca/nome-matching.ts](../../apps/api/src/modules/mapa-forca/nome-matching.ts)** (MODIFIED)

- `ResolveResult` ganha campo opcional `divergencia?: { postoRef, postoEfetivo, nomeGuerraRef, nomeGuerraEfetivo }`
- Caminho `if (ref.nf) { const direct = this.byNf.get(ref.nf); if (direct) ...}`: compara via `normalizeForCompare` posto e nomeGuerra; se algum diverge, devolve `divergencia` no resultado
- Nova função `normalizeForCompare(s)`: uppercase + NFD + remove acento + remove whitespace/`. ,`. Tolera diferenças cosméticas ('2º SGT' ↔ '2ºSGT', ' BARCELLOS ' ↔ 'BARCELLOS')

**[apps/api/src/modules/escalas-especiais/escalas-especiais.service.ts](../../apps/api/src/modules/escalas-especiais/escalas-especiais.service.ts)** (MODIFIED)

- `upsertNoPostgres` reescrito:
  1. `findUnique({ ..., include: { atos: true } })` carrega atos existentes
  2. Se não existir, `create` cascade (caminho otimizado para 1ª importação)
  3. Caso contrário: computa `keyExistente`/`keyNovo` → `Map`/`Set` → `toAddNovos` + `toRemoveIds`
  4. `deleteMany({ where: { id: { in: toRemoveIds } } })` apenas para os atos a remover
  5. `update({ ..., atos: { create: toAddNovos.map(toAtoCreate) } })` para os novos
  6. Log: `Escala Especial MM/YYYY diff: +N novos, -M removidos, K mantidos.`

### Tests

**[apps/api/src/modules/mapa-forca/nome-matching.test.ts](../../apps/api/src/modules/mapa-forca/nome-matching.test.ts)** (MODIFIED)

3 testes novos:

1. **`marca divergencia quando NF casa mas nomeGuerra é diferente`** — ref com NF 3037509 + nomeGuerra `'BARCELOS'` (grafia errada) → `resolved.nf === '3037509'` + `divergencia.nomeGuerraEfetivo === 'BARCELLOS'`
2. **`marca divergencia quando posto na ref é diferente do efetivo`** — ref com NF 3037509 + posto `'3ºSGT'` (desatualizado) → `divergencia.postoEfetivo === '2ºSGT'`
3. **`NÃO marca divergencia quando posto/nomeGuerra na ref batem`** — ref com `'2º SGT'` + `' BARCELLOS '` (whitespace) → `divergencia` é `undefined`

**[apps/api/src/modules/escalas-especiais/escalas-especiais.service.test.ts](../../apps/api/src/modules/escalas-especiais/escalas-especiais.service.test.ts)** (MODIFIED)

- Mock `deleteMany`: suporta `where: { id: { in: [...] } }` (S2.12c) além de `escalaEspecialId` (back-compat)
- Mock `update`: quando `data.atos.create` é passado, **APENDA** em vez de substituir (deleteMany já cuidou dos removidos)
- 4 testes novos:
  1. **`re-import idêntico mantém todos os atos`** — save × 2 mesma escala → `atos.length === 3` preservado
  2. **`re-import com 1 ato substituído remove o antigo e adiciona o novo`** — SGT BISSOLI → CB FABRE
  3. **`re-import com ato adicional mantém os antigos + adiciona`** — 3 → 4 atos
  4. **`re-import com 1 ato removido apaga só ele`** — 3 → 2 atos do dia 01/05
