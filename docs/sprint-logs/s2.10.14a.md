# Sprint S2.10.14a — Remove bootstrap fallback Sheets-DB (3 services)

**Data:** 2026-05-28
**Foco:** Etapa 1/3 do roadmap [remocao-sheets-db-roadmap.md](../runbooks/remocao-sheets-db-roadmap.md) — eliminar o fallback `bootstrapFromSheetsDbIfEmpty()` dos 3 últimos consumers do `SheetsDbService` em runtime.
**Tech Lead:** 2º SGT Heitor Barcellos Coelho

## Critérios de Pronto (DoD)

- [x] `EscalasService`: removido `@Optional sheetsDb`, imports e método `bootstrapFromSheetsDbIfEmpty()`
- [x] `EscalasEspeciaisService`: idem
- [x] `NotasServicoService`: idem + classe não implementa mais `OnModuleInit` (single-purpose CRUD)
- [x] 3 módulos: `SheetsDbModule` removido dos imports
- [x] `IntegracoesModule`: `SheetsDbModule` removido dos imports (dep órfã)
- [x] `IntegracoesService`: comentário S2.10.9d atualizado para S2.10.14a
- [x] Tests obsoletos (`sheets-db-integration.test.ts`) deletados — testavam dual-write + bootstrap removidos
- [x] Pipeline verde: typecheck + lint + format + test
- [x] **655 api + 30 web = 685 passing** (-7 vs S2.10.14: 7 testes de regressão `sheets-db-integration.test.ts` removidos)

## Por que mudar

`bootstrapFromSheetsDbIfEmpty()` era código morto desde S2.10.9d (dual-write encerrado; Postgres canônico em runtime há 2 semanas sem incidente). Mantê-lo:

- Acoplava EscalasService/EscalasEspeciaisService/NotasServicoService ao módulo `sheets-db/` que será deletado em 14b
- Aumentava o blast radius de cada boot (3 chamadas a Google Sheets API que sempre retornavam `isEnabled()=false` em prod sem credencial)
- Confundia leitor de código sobre qual é a fonte da verdade
