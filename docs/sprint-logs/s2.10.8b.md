**Data:** 2026-05-19
**Tech Lead:** 2º SGT Heitor Barcellos Coelho — NF 3037509
**PR:** TBD

## Motivação

Segunda das 4 sub-sprints do **S2.10.8**. Resolve diretamente o **item 1 do Tech Lead** (lentidão): `TrocaAutorizada` é tocada toda vez que o `GET /mapa-forca?data=...` chama `listByData(dataIso)`. Hoje (S2.10.7e) isso significa fetch da planilha externa com cache TTL 5min. Migrar para Postgres + sync orchestrator elimina esse fetch crítico do path do request.

Trocas autorizadas é o **maior impacto** porque é uma das planilhas mais tocadas pela cascata do Mapa Força.

## Smoke test pós-deploy

1. **Sync no startup**
   - Log: `[SyncOrchestratorService] Startup sync: 2 source(s) registradas — dispensas-import, trocas-autorizadas-import`
   - SyncLog table tem 2 entries com `trigger='startup'`

2. **`SELECT COUNT(*) FROM trocas_autorizadas`** → N (era 0)
   - Antes: 0 (tabela nunca populada)
   - Após sync inicial: ~30-100 (depende da planilha do mês)

3. **`GET /mapa-forca?data=2026-05-17`** mais rápido
   - Antes: `await trocasAutorizadas.listByData(dataIso)` → fetch HTTP (até 15s no 1º request)
   - Depois: query Postgres (< 100ms)
   - Cascata total do GET diminui de ~45-60s para ~30-45s (resta MF CIODES + Efetivo+QDI)

4. **Menu `/configuracoes/integracoes`**
   - "Trocas Autorizadas → Postgres (upsert)" agora aparece com badge **💾 Persistido** (era ⚡ Tempo-real)
   - "Sincronizar todas" no topo agora roda 2 sources (Dispensas + Trocas)

5. **Cron 00/06/12/18h**
   - SyncLog table tem entries de `trigger='cron'` após próxima janela

6. **Trocas Autorizadas em uso real**
   - Editar a planilha (adicionar nova linha)
   - Aguardar próxima sync (cron OU 5min cache do `syncIfStale`)
   - `GET /mapa-forca?data=...` reflete nova troca
