## Por que mudar

S2.10.11a trocou 30 chamadas seriais a `getMapaForcaDoDia` por uma
única leitura de `EscalaMensal`. Resolveu o problema de latência e dos
timeouts silenciosos. **Mas o Tech Lead reportou em 2026-05-23 que
escalas mensais E escalas especiais dele ainda não apareciam.** A
investigação identificou 3 lacunas no método novo:

### Lacuna 1 — Filtro strict-equal exclui entries com NF=null

```ts
// escalas.service.ts:321 antes de S2.10.11d
if (c.militar.nf !== nf) continue;
```

Se o parser XLSX não resolveu o NF de uma célula (nome ambíguo,
abreviação não-canônica), `militarNf` fica null no DB. O método antigo
(`getMapaForcaDoDia`) aplicava `NomeMatcher` em runtime contra o
efetivo consolidado. O método novo descartava silenciosamente.

### Lacuna 2 — Não cobre Mergulho/Salvamar

`listEscaladosDoMilitarNoRange` iterava apenas `composicaoEntries`. Os
campos `escala.mergulho` e `escala.salvamar` (JSON com
`equipesPorQuinzena.q1/q2`) eram ignorados. Heitor não aparecia quando
escalado como supervisor de Salvamar ou chefe/motorista/mergulhador de
uma equipe MERGULHO.

### Lacuna 3 — Escala Especial silenciosa

`coletarEscalaEspecial` já chamava NomeMatcher como fallback, mas
quando o matcher falhava o ato sumia **sem nenhum log**. Operador não
tinha como diagnosticar.

## Achados

- **`Prisma.JsonNull` é sentinel truthy** — quando uma escala não tem
  mergulho ou salvamar, o campo Json é gravado como `Prisma.JsonNull`
  (objeto), não `null`. O serializer `toEscalaMensal` faz `(row.X ??
  undefined)` mas `??` não dispara para sentinelas. Solução:
  optional chaining `escala.mergulho?.porDia` no consumer.
- **NomeMatcher já tem todos os índices necessários** (nf, posto+nome,
  nome só, tokens) — bastou passar o efetivo. Custo desprezível com
  cache do `EfetivoService`.
- **Tradeoff aceito**: o método não aplica swaps manuais nem ativações
  de recurso do Fiscal (esses eram aplicados em `getMapaForcaDoDia`).
  Se o usuário entrou via swap pós-importação, ainda não aparece. Fica
  para sprint futura — solução envolve consultar `AjustesPreviaService`
  por dia do range.
