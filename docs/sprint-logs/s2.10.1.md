## Decisões consolidadas no ADR-014

| #   | Decisão                                                                      | Por quê                                                      |
| --- | ---------------------------------------------------------------------------- | ------------------------------------------------------------ |
| D1  | Supabase Free + região São Paulo + PgBouncer                                 | Custo 0 + latência ES + serverless friendly                  |
| D2  | Prisma 5 (já estabelecido em ADR-001)                                        | Continuidade                                                 |
| D3  | IDs `cuid()`                                                                 | Ordenado por tempo + curto + sem conflito em insert paralelo |
| D4  | Soft delete em editáveis; hard delete em re-importáveis                      | Auditoria vs simplicidade                                    |
| D5  | JSONB em estruturas complexas (MapaForcaDiario.payload, EscalaMensal.avisos) | Acesso em bloco; normalizar daria 10+ tabelas sem ganho      |
| D6  | 5 sub-sprints sequenciais                                                    | Risco vs big-bang                                            |
| D7  | Sheets-DB continua como espelho                                              | Inspeção institucional + defense-in-depth                    |
| D8  | Seed one-shot, não recorrente                                                | Direção passa a ser Postgres → Sheets                        |
| D9  | RLS só em S2.10.5                                                            | Precisa do auth.users mapeado primeiro                       |

## Riscos identificados (mitigações)

| Risco                                             | Mitigação                                                                           |
| ------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Schema mudará durante implementação dos services  | OK — `prisma migrate dev` cria novas migrations conforme avança                     |
| Migration falha em produção                       | Vercel deploy bloqueia se `migrate deploy` falha; backup Supabase é diário          |
| Tech Lead não configura Supabase antes de S2.10.2 | S2.10.2 fica bloqueada (não dá pra começar sem `DATABASE_URL`) — comunicar urgência |
