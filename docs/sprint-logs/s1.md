# Sprint S1 — Auth + RBAC

**Início:** 2026-05-08
**Foco:** Login com NF + senha (CPF inicial) + estrutura de papéis (RBAC)
**Duração estimada:** 5-6 dias úteis
**Tech Lead:** 2º SGT Heitor Barcellos Coelho

## Objetivo

Permitir que um militar abra o ARGUS, faça login com seu NF e senha, e veja uma tela home customizada
conforme seu(s) papel(éis). Tela home no S1 é apenas um cartão de boas-vindas com nome, posto e
papéis — o conteúdo virá em sprints seguintes.

## Descobertas e decisões

### Descoberta importante (2026-05-08): Planilha Efetivo é pública

Verificado via `curl` que a planilha de Efetivo do Sargenteante (gid `1379090962`) é
**publicamente acessível via export CSV** (sem OAuth). Isso destranca o S2 do bloqueio anterior
por "auth Sheets indefinida" e elimina a necessidade de Service Account ou OAuth User Delegation
**para leitura**. A decisão de auth segue válida apenas para escrita do Mapa Força (S9).

### Issue institucional registrada

CPFs reais expostos no CSV público da planilha de Efetivo. Não é escopo do projeto resolver, mas
vale reportar ao Sargenteante e DPO institucional. **Nenhum CPF real foi armazenado no código
do ARGUS** — apenas CPFs fake gerados para testes.

### Decisões técnicas (resumidas no ADR-002)

- **bcrypt cost 12** (NIST), configurável via `BCRYPT_COST`
- **JWT HS256** com TTL **8h** (alinhado a turno operacional)
- **Cookie `argus_session`** httpOnly, SameSite=Lax, Secure em produção
- **Rate limit in-memory** por NF (5 falhas em 5min → bloqueio 15min)
- **Vitest unificado** (consolidação R-4 da auditoria) — sem Jest
- **React Router v7** com Outlet/protected routes
- **`@argus/shared-types`** centraliza Zod schemas usados por front e back

## Verificação end-to-end manual

```bash
# Backend
pnpm dev:api  # porta 3000

# Em outro terminal:
curl -i -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"nf":"3037509","senha":"11122233344"}' \
  -c /tmp/argus-cookies.txt
# → 200 OK + Set-Cookie: argus_session=...

curl http://localhost:3000/auth/me -b /tmp/argus-cookies.txt
# → {"nf":"3037509","nome":"HEITOR BARCELLOS COELHO",...,"primeiroAcesso":true}

# 5x senha errada → última 423
for i in $(seq 1 5); do
  curl -X POST http://localhost:3000/auth/login \
    -H "Content-Type: application/json" \
    -d '{"nf":"3037509","senha":"errada"}' -w "\nstatus=%{http_code}\n"
done
# → 401, 401, 401, 401, 423

# Frontend
pnpm dev:web  # porta 5173
# Browser:
# - http://localhost:5173/ → redireciona para /login
# - NF=3037509 + senha=11122233344 → redireciona para /trocar-senha (primeiroAcesso)
# - Trocar para senha forte → redireciona para / (home)
# - Sair → /login
```

## Riscos S1 conhecidos (revisão final)

- **CPFs reais expostos no CSV público:** issue institucional registrada, fora do escopo do
  ARGUS resolver. Comunicar ao Sargenteante (1º SGT De Mattos) e DPO institucional.
- **Mock storage perde estado em restart:** trocas de senha não persistem entre boots em S1.
  Resolvido em S5 com Prisma+Supabase.
- **Estimativa:** ~5,5 dias plano × tempo real (a apurar). Possível overrun no setup do
  `packages/shared-types` (1ª vez compilando dist + ajuste de tsconfig).
- **React Router v7 + jsdom:** `createBrowserRouter` falha em testes jsdom; mitigado usando
  `<MemoryRouter>` em testes que exigem rota.
