## Estratégia "rascunho ⊕ override"

A PD é um documento muito grande (15+ seções). Tentar persistir tudo
seria caro e propenso a inconsistência (a Prévia muda sob a PD). Em vez
disso:

1. **Rascunho** é sempre derivado on-the-fly da Prévia/Servico.
2. **Override** é só os campos que o Fiscal de fato editou (PUT envia
   um objeto parcial; backend mescla por chave).
3. **GET** retorna `merge(rascunho, override)` + timestamp do último
   edit.

Vantagem: se a Prévia for atualizada (nova dispensa cadastrada, nova
NS), o rascunho reflete imediatamente. Override só sobrescreve onde o
Fiscal escolheu colocar texto manual.

## Mapeamento Prévia → Parte Diária

| Seção PD                             | Fonte                                                          |
| ------------------------------------ | -------------------------------------------------------------- |
| Cabeçalho (equipe + data + sucessor) | `previa.equipe` + `diaSeguinteIso(data)`                       |
| ASSUNÇÃO DE SERVIÇO                  | `previa.fiscal` + override `fiscalQuePassa`                    |
| ESCALAS OPERACIONAIS                 | `previa.composicaoMf` (chefe + motorista + operadores)         |
| TROCAS DE SERVIÇO                    | `previa.trocas` + `previa.trocasEscalaEspecial`                |
| ESCALA ESPECIAL                      | `previa.escalaEspecialAtos`                                    |
| ISEO                                 | NS do dia onde código/descrição contém "ISEO"                  |
| IDEO Fiscal                          | `previa.textoAtestadoIdeoFiscal` (S6i)                         |
| CUMPRIMENTO DE OS / NS               | `previa.notasServico`                                          |
| ALTERAÇÕES DIVERSAS                  | `previa.dispensas` + `previa.atestados` + `alteracoesDiversas` |
| Guarda, Faxina, Ronda, Passagem      | Override puro (texto livre)                                    |
| Almoxarifado, Instrução, Viaturas    | Override puro                                                  |
| Ocorrências Confeccionadas           | Override puro (integração BAON futura)                         |

## Achados durante a implementação

- **Bug de capture group em `diaSeguinteIso`:** primeira versão do regex
  `/^\d{4}-\d{2}-\d{2}$/` não tinha capture groups — destructuring
  retornava `undefined → NaN → "NaN-NaN-NaN"`. Fix: regex separado
  `dataIsoParts = /^(\d{4})-(\d{2})-(\d{2})$/`.
- **`vtrStatus` discrepância:** schema diz uppercase
  (`DISPONIVEL/BAIXADA/EMPRESTADA`) mas `previa.service.test.ts` legacy
  usa `'operacional'/'baixada'` lowercase via cast `as Viatura`. A
  comparação no frontend usa o valor canônico do schema (`'BAIXADA'`).
  Não foi alterado o teste legacy nesta PR — é dívida técnica
  preexistente fora do escopo.
- **Override mescla por chave:** ausência da chave no PUT = manter
  rascunho. `null` (em campos nulláveis) = limpar rascunho. String
  vazia em texto = override válido (mostra vazio).
- **Print CSS:** `print:hidden` na toolbar e nos botões "+ linha", `×`
  remove. Inputs editáveis ficam com `print:border-none print:bg-white
print:p-0` para sumirem visualmente quando impressos.
