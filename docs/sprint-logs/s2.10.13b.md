## Por que mudar

A página `/cadastros/efetivo` mostrava apenas militares da 1ª Cia/1º BBM
por causa de **dois filtros encadeados**:

1. **Parser `parseQdiDadosCsv` filtrava `LOCAL == "1ª1º"`** no CSV da aba
   QDI/DADOS — descartando todos os militares de outras unidades CBMES.
2. **`EfetivoService.list` aplicava `somente1aCia` por default** (checkbox
   marcado no frontend) — filtrando órfãos do EFETIVO.

O Tech Lead precisa consultar militares de TODAS as unidades CBMES (CG,
CEPDEC, DAL, CORREG, DGP, 1ª1º, 2ª1º, etc.) com filtro por unidade
escolhido em dropdown, com default = unidade do user logado.

### Decisão sobre migration "DROP+recreate"

O plano S2.10.13 propunha DROP+recreate da tabela `militares` para
limpar dados antigos. **Não foi feito** — FKs `ON DELETE RESTRICT` em
Dispensa/Atestado/Ferias inviabilizam DELETE sem perder cadastros
manuais valiosos do sargenteante. **Abordagem alternativa**: apenas
adicionar índice `unidade` (migration mínima). O próximo sync via botão
"🔄 Sincronizar" faz UPSERT em todos os militares — existentes ganham
`unidade` populada (parser sem filtro popular `unidade` a partir de
`lotacao` da planilha QDI/DADOS); novos são criados para outras unidades.
Resultado equivalente, **zero perda de dados** das tabelas filhas.

### Smoke pós-deploy

1. **Após deploy** (migration aplicada): índice `militares_unidade_idx` criado
2. **Botão "🔄 Sincronizar Agora"** em /cadastros/efetivo → próximo sync importa TODAS as unidades; UPSERT atualiza `Militar.unidade` para todos
3. **`GET /efetivo/unidades`** retorna lista de unidades distintas presentes no Postgres
4. **Página /cadastros/efetivo**:
   - 1ª visita: select já mostra a unidade do user logado como default (com marcação "(minha unidade)")
   - Trocar para "Todas as unidades" → lista cresce drasticamente
   - Trocar para "CG" → filtra para militares do Comando Geral
   - Buscar "MAJ" + unidade "CEPDEC" → combinação aplicada client+server-side
5. **Retrocompat**: chamadas externas com `?somente1aCia=true` continuam funcionando (vira `unidade=1ª1º`)
6. **Performance**: índice `unidade` torna o filter Postgres-side rápido mesmo com milhares de militares

## Achados

- **FKs ON DELETE RESTRICT** em Dispensa/Atestado/Ferias inviabilizam DROP+recreate
  da tabela Militar sem perder dados manuais. Solução: apenas adicionar
  índice + parser sem filtro. UPSERT no sync reconcilia o resto.
- **`incluirEfetivoOrfao: true` no `list()`** muda regra do S6a-fix item 2.
  Aceitável: o S6a-fix existia para preservar "só 1ª Cia"; agora a lista é
  CBMES inteiro, então órfãos do EFETIVO devem aparecer.
- **`mergeThreeSources` precisava ser cuidadoso** com `unidade`: QDI 1ª1º
  setava com valor longo ("1ª Cia / 1º BBM"); DADOS popular o campo via
  `lotacao` (LOCAL da planilha = "1ª1º"). Mantemos `unidade` do QDI quando
  presente; só usa `lotacao` como fallback quando QDI ausente.
- **Default UX do select** = unidade do user logado, descoberta via
  `efetivoFindByNf(user.nf)`. Não precisei adicionar `unidade` ao
  UserSession (menos mudança no auth).
